# 📦 분실물 통합 관리 시스템

> **청주도시공사 시설(수영장·다목적체육관 등) 분실물 관리 시스템**  
> 시설 담당자·관리자·이용객이 사용하는 웹 기반 분실물 등록·조회·반환 시스템입니다.

---

## 📖 이 시스템은 뭔가요?

시설(수영장·다목적체육관 등) 이용중 분실물이 발생하면:

```
1. 시설 담당자가 분실물을 등록합니다 (사진·설명·보관 위치)
2. 이용객이 QR코드를 스캔하거나 웹페이지에서 분실물을 조회합니다
3. 물건을 찾으러 오면 수령인 정보를 기록하고 반환 처리합니다
4. 일정 기간 미수령 시 폐기 처리합니다
```

---

## 🖥️ 화면 구성 (파일 설명)

| 파일 | 누가 사용하나요? | 어떤 화면인가요? |
|:---|:---|:---|
| `lost_and_found.html` | **시설 담당자** | 시설 코드로 로그인 → 분실물 등록·관리·수령처리 |
| `lost_and_found_admin.html` | **전체 관리자** | 관리자 코드로 로그인 → 모든 시설의 분실물 총괄 관리 |
| `lost_and_found_view.html` | **이용객 (일반인)** | 로그인 없이 → 분실물 목록 조회만 가능 |
| `qrcode.html` | **시설 담당자** | 분실물 조회용 QR코드 생성·인쇄 |
| `privacy_policy.html` | 모두 | 개인정보 처리방침 (법적 필수) |
| `terms_of_use.html` | 모두 | 이용약관 (법적 필수) |

### 사용 흐름

```
이용객: "물건을 잃어버렸어요"
    ↓
시설 담당자: lost_and_found.html에서 분실물 등록
    ↓
이용객: lost_and_found_view.html 또는 QR코드로 조회
    ↓
이용객: "제 물건이에요!" → 방문
    ↓
시설 담당자: 수령인 이름·연락처 기록 → 수령 완료 처리
```


> **💡 1번 "Firebase Authentication"이 뭔가요?**
>
> 현재 시설코드·관리자코드로 로그인하는 기능은 **이미 작동하고 있습니다.**  
> 다만 이 로그인은 **"브라우저(사용자 PC)"에서만 확인**합니다.
>
> Firebase Authentication은 **"구글 서버"에서 신원을 확인**하는 방식이라,  
> 설령 누군가 개발자 도구(F12)로 로그인 화면을 우회하더라도  
> **구글 서버가 데이터 접근 자체를 차단**합니다.
>
> | 비교 | 현재 (시설·관리자 코드) | Firebase Auth (미적용) |
> |:---|:---|:---|
> | 비유 | 건물 입구의 비밀번호 잠금장치 | 전자 출입카드 시스템 |
> | 확인하는 곳 | 사용자 PC (브라우저) | 구글 서버 |
> | 우회 가능성 | 개발자 도구로 가능 (전문 지식 필요) | 구글 서버가 차단하므로 불가 |
>
> **현실적 위험은 낮지만**, 향후 보안 강화 시 도입을 검토할 수 있습니다.  
> 도입 자체는 Firebase를 이미 사용 중이므로 **난이도가 높지는 않으나**,  
> 로그인 방식이 바뀌므로 4개 HTML 파일의 인증 코드를 모두 수정해야 합니다.  
> (AI 코딩 도구와 함께 작업하면 충분히 가능한 수준입니다)

> **💡 2번 "HTTPS 서버 헤더"는 왜 대체 적용인가요?**
>
> 보안 설정(클릭재킹 방지 등)을 적용하는 방법이 **2가지**입니다:
>
> | 방법 | 비유 | 우리 시스템 |
> |:---|:---|:---:|
> | **서버 헤더** (가장 확실) | 문에 전자 잠금장치 설치 | ❌ GitLab Pages에서 설정 불가 |
> | **meta 태그** (대체 방법) | 문에 "출입금지" 안내문 부착 | ✅ **현재 이 방법으로 적용 중** |
>
> GitLab Pages는 서버 설정을 직접 건드릴 수 없어서,  
> HTML 코드 안에 meta 태그로 넣는 **대체 방법을 사용 중**입니다.  
> 대부분의 브라우저에서 정상 작동하므로 **실질적 문제는 없습니다.**
>
> 만약 향후 자체 서버(예: Nginx, Apache)로 이전하면 서버 헤더로 교체할 수 있습니다.
