## 2. 관리자 코드(비밀번호) 변경하는 법

> ⚠️ **중요**: 관리자 코드는 코드에 직접 적혀있지 않습니다.  
> "SHA-256 해시값"이라는 암호화된 값으로 저장되어 있습니다.  
> 비밀번호를 변경하려면 아래 절차를 따라야 합니다.

### 절차 (총 4단계)

#### STEP 1. 새 비밀번호 정하기

- 예시: `ADMIN2025`
- **규칙**: 영문 대문자 + 숫자 조합, 6자리 이상 권장

#### STEP 2. 해시값 만들기

1. 인터넷 브라우저에서 아래 사이트에 접속합니다:  
   👉 https://emn178.github.io/online-tools/sha256.html
2. 왼쪽 입력란에 새 비밀번호를 **대문자로** 입력합니다 (예: `ADMIN2025`)
3. 오른쪽에 나오는 긴 영문+숫자 문자열이 **해시값**입니다
4. 이 해시값을 **복사**합니다

#### STEP 3. 코드에 해시값 붙여넣기

1. 아래 **2개 파일**을 메모장이나 VS Code로 엽니다:
   - `lost_and_found.html`
   - `lost_and_found_admin.html`
2. `Ctrl + F`로 `ADMIN_HASH`를 검색합니다
3. 기존 해시값을 **새 해시값으로 교체**합니다

```
// 변경 전 (예시)
const ADMIN_HASH = "4d8365...기존값...";

// 변경 후 (예시)
const ADMIN_HASH = "새로만든해시값을여기에붙여넣기";
```

#### STEP 4. 테스트

1. 브라우저에서 시스템을 열고 새 비밀번호로 로그인 테스트
2. 정상 작동 확인 후 서버에 업로드

> 💡 **팁**: 해시값은 원래 비밀번호로 되돌릴 수 없습니다.  
> 그래서 비밀번호 자체는 **별도로 안전한 곳에 메모**해 두세요.

## 3. 시설 코드 관리하는 법

시설 코드는 Firebase의 `facilities` 컬렉션에서 관리됩니다.

### 시설 추가/수정/삭제

- **관리자 대시보드** (`lost_and_found_admin.html`)에서 로그인 후
- "시설 관리" 메뉴에서 시설을 추가·수정·삭제할 수 있습니다
- 별도의 코드 수정은 필요 없습니다

### 시설 코드 규칙

| 항목 | 권장 사항 |
|:---|:---|
| 형식 | 영문+숫자 (예: `GYM001`, `SWIM02`) |
| 길이 | 3~10자 |
| 공유 범위 | 해당 시설 담당자에게만 전달 |

## 4. Firebase 보안 규칙 설정하는 법

> 💡 **Firebase 보안 규칙이란?**  
> "누가 데이터를 읽고 쓸 수 있는지"를 정하는 규칙입니다.  
> 지금은 누구나 읽고 쓸 수 있는 상태(**테스트 모드**)일 수 있으므로,  
> 아래 규칙을 적용하면 보안이 강화됩니다.

### 설정 방법

1. [Firebase 콘솔](https://console.firebase.google.com/)에 로그인
2. 해당 프로젝트 선택
3. 왼쪽 메뉴에서 **Firestore Database** → **규칙** 탭 클릭
4. 아래 내용을 복사해서 붙여넣기

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 분실물 시스템 데이터
    match /artifacts/{appId}/public/data/{document=**} {
      // 모든 사용자가 읽기 가능 (이용객 조회용)
      allow read: if true;
      // 쓰기는 인증 없이도 허용 (현재 구조상 클라이언트에서 직접 쓰기)
      // ⚠️ 향후 Firebase Auth 도입 시 아래 줄을 변경하세요
      allow write: if true;
    }
    // 그 외 모든 경로는 차단
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
```

5. **게시** 버튼 클릭

> ⚠️ **주의**: `allow write: if true`는 현재 인증 체계(클라이언트 직접 접근) 때문에 열어둔 것입니다.  
> 향후 Firebase Authentication을 도입하면 `allow write: if request.auth != null`로 변경하세요.

## 6. 문제가 생겼을 때 (비상 대응)

### 🚨 "시스템이 아예 안 열려요"

1. 인터넷 연결 상태 확인
2. GitLab Pages가 정상인지 확인 (GitLab 로그인 → 해당 프로젝트 → Pages)
3. Firebase 콘솔에서 Firestore 상태 확인
4. 해결 안 되면 → 정보전산팀에 연락

### 🚨 "관리자 비밀번호를 잊어버렸어요"

1. SHA-256 해시는 되돌릴 수 없으므로, **새 비밀번호를 정해서 해시값을 다시 만들어야** 합니다
2. 위의 [2. 관리자 코드 변경하는 법](#2-관리자-코드비밀번호-변경하는-법) 절차를 따르세요

### 🚨 "잘못된 수정을 해서 시스템이 망가졌어요"

1. `versions/` 폴더에 이전 버전이 보관되어 있습니다
2. 원하는 버전의 파일을 루트(최상위 폴더)에 복사하면 원상 복구됩니다

```
복구 예시:
versions/v3_감사추적/ 안의 파일들을 → 루트 폴더로 복사
```

| 버전 | 내용 | 복구 시 상태 |
|:---|:---|:---|
| `v0_원본/` | 최초 원본 (보안 조치 없음) | 보안 없는 원래 상태로 돌아감 |
| `v1_보안강화/` | 비밀번호 암호화 + 법적 문서 | Phase 1까지 적용된 상태 |
| `v2_접근성개선/` | 줌 허용 + 보안 메타태그 | Phase 2까지 적용된 상태 |
| `v3_감사추적/` | 자동 로그아웃 + 감사 로그 | Phase 3까지 적용된 상태 (최신) |

### 🚨 "데이터가 이상하게 변경/삭제되었어요"

1. Firebase 콘솔 → Firestore → `audit_logs` 컬렉션 확인
2. 해당 시간대의 로그를 찾아 **누가, 언제, 무엇을 변경했는지** 확인
3. 필요 시 관리자 대시보드에서 데이터 복원
