### Phase 1: 🔴 긴급 보안 · 법적 필수 사항 — ✅ 완료

> **개인정보보호법 위반 및 감사 시 즉시 지적될 수 있는 항목**

#### ✅ 1-1. 관리자 인증 보안 강화

- **문제**: `ADMIN_CODE = "ADMIN777"` 소스 코드 평문 노출
- **조치**: SHA-256 해시 비교 방식 + 5회 시도 제한(30초 잠금) + 접속 로그 기록
- **적용 파일**: `lost_and_found.html`, `lost_and_found_admin.html`

```javascript
// 변경 전
const ADMIN_CODE = "ADMIN777";

// 변경 후 — 해시값만 저장, 원문 비노출
const ADMIN_HASH = "4d8365e1bfd2...";
async function verifyAdminCode(input) {
  const hash = await sha256Async(input.trim().toUpperCase());
  return hash === ADMIN_HASH;
}
```

#### ✅ 1-2. 개인정보 처리방침 페이지 신규 생성

- **법적 근거**: 개인정보보호법 제30조
- **파일**: `privacy_policy.html` (9개 조항)
- **주요 내용**: 수집 목적(유실물법 제11조), 보유 기간, 파기 절차, Firebase 위탁 고지

#### ✅ 1-3. 수령 완료 화면 법적 근거 안내

- **조치**: 유실물법 제11조 근거 안내 + 개인정보 처리방침 링크
- **결정 사항**: 유실물법에 근거한 수집이므로 동의 체크박스 불필요 → 법적 근거 고지 방식 채택
- **적용 파일**: `lost_and_found.html`

#### ✅ 1-4. 푸터 법적 필수 링크

- **적용**: 4개 페이지 전체
- **내용**: `운영기관: 청주도시공사 | 개인정보 처리방침 | 이용약관 | 문의: 043-820-7242`

### Phase 2: 🟡 보안 강화 및 웹 접근성 개선 — ⏳ 대기

#### 2-1. 웹 접근성 기본 개선

- `user-scalable=no` → `user-scalable=yes` 변경 (줌 허용)
- 주요 인터랙티브 요소에 ARIA 속성 추가
  - `role="dialog"` (모달), `role="navigation"` (탭), `role="alert"` (토스트)
  - `aria-label` (아이콘 버튼), `aria-required` (필수 입력), `aria-expanded` (접기/펼치기)
- 포커스 트랩 (모달 열림 시 Tab 키 범위 제한)
- Skip navigation 링크 추가

#### 2-2. 보안 메타태그 추가

```html
<meta http-equiv="X-Content-Type-Options" content="nosniff"/>
<meta http-equiv="X-Frame-Options" content="DENY"/>
<meta name="referrer" content="strict-origin-when-cross-origin"/>
```

#### 2-3. React 프로덕션 빌드 전환

```html
<!-- 변경 전 (development) -->
<script src=".../react.development.js"></script>

<!-- 변경 후 (production) — 성능 향상 + 디버그 정보 비노출 -->
<script src=".../react.production.min.js"></script>
```

#### 2-4. 에러 메시지 정제 (나머지 파일)

```javascript
// 변경 전: 내부 정보 노출
showToast("오류: " + err.message, "error");

// 변경 후: 사용자 친화적 메시지
showToast("처리 중 오류가 발생했습니다.", "error");
console.error("[시스템]", err); // 개발자 콘솔에만
```

#### 2-5. 입력 데이터 정제 (Sanitize)

```javascript
function sanitizeInput(str, maxLen = 200) {
  return String(str || "")
    .replace(/<[^>]*>/g, '')    // HTML 태그 제거
    .replace(/[<>&"']/g, '')    // 특수문자 제거
    .trim().slice(0, maxLen);
}
```

### Phase 3: 🟢 감사 추적 · 세션 관리 — ⏳ 대기

#### 3-1. 감사 로그 강화

- 모든 데이터 변경 시 변경 전·후 값을 `audit_logs`에 기록
- 로그에 세션 ID + 시설코드 + 타임스탬프 기록

```javascript
async function logAudit(action, details) {
  await db.collection(AUDIT_LOGS_COL).add({
    action,     // "MODIFY", "STATUS_CHANGE", "DELETE"
    details,    // { before: {}, after: {} }
    sessionId:  getSessionId(),
    facilityCode: currentFacilityCode,
    actedAt: firebase.firestore.FieldValue.serverTimestamp(),
  });
}
```

#### 3-2. 세션 타임아웃

- 시설 담당자: 30분 미조작 시 자동 로그아웃 + 5분 전 경고
- 관리자: 20분 타임아웃 + 로그아웃 시 세션 완전 파기

#### 3-3. Firestore Security Rules 가이드

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /artifacts/{appId}/public/data/{document=**} {
      allow read: if true;
      allow write: if request.auth != null;
    }
  }
}
```

> **주의**: Firebase Console에서 직접 설정 필요. Firebase Authentication 도입 전까지는 서버 사이드 접근 제어 불가.

## ⚠️ 구조적 한계 및 향후 과제

> 현재 아키텍처(Firebase 클라이언트 직접 접근 + 정적 HTML 호스팅)의 **구조적 한계**입니다.  
> 완전한 해결을 위해서는 백엔드 서버 도입이 필요합니다.  
> 감사 시 **"현재 구조의 한계로 대체 조치를 시행 중"**이라고 설명할 수 있도록 문서화합니다.

| 한계 항목 | 현재 대체 조치 | 향후 개선 방향 |
|:---|:---|:---|
| Firebase Authentication 미사용 | 관리자 코드 해시화 + 시도 횟수 제한 | Firebase Auth 도입 |
| 서버 사이드 접근 제어 없음 | 클라이언트 사이드 검증 + Firestore Rules | Firebase Cloud Functions |
| 개인정보 암호화 저장 불가 | Firestore 기본 암호화 (Google 인프라) 의존 | 필드 레벨 암호화 |
| CSP 헤더 설정 불가 (정적 호스팅) | `<meta>` 태그로 대체 | 서버 사이드 헤더 설정 |
| API Key 클라이언트 노출 | Firestore Rules로 보호 + API Key 도메인 제한 | Firebase Auth + Cloud Functions |
