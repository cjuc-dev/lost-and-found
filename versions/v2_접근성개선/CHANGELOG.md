## 변경 내역

### 2-1. 웹 접근성 — 줌 허용 ♿

> 📜 **법적 근거**
> - **장애인차별금지법 제20조** (정보접근) — "장애인이 전자정보에 접근·이용할 수 있도록 필요한 수단을 제공하여야 한다"
> - **지능정보화 기본법 제46조** (디지털포용) — "모든 국민이 정보통신서비스에 원활하게 접근하고 이용할 수 있도록 하여야 한다"
> - **WCAG 2.1 Level AA — 지침 1.4.4** (텍스트 크기 조절) — "콘텐츠의 기능이나 정보의 손실 없이 텍스트를 200%까지 확대할 수 있어야 한다"

- `user-scalable=no` → `user-scalable=yes`, `maximum-scale=5.0` 변경
- **대상**: 4개 파일 전체 + `qrcode.html`

> 💡 **쉽게 말하면**: 스마트폰에서 **두 손가락으로 화면을 확대**할 수 있게 한 것입니다.
> 기존에는 확대가 막혀 있어 시력이 안 좋은 분이 글씨를 크게 볼 수 없었습니다.
> 법적으로 장애인·고령자도 사용할 수 있어야 하므로 줌을 막으면 위반입니다.

### 2-2. 보안 메타태그 추가 🔐

> 📜 **법적 근거**
> - **개인정보보호법 제29조** (안전조치의무) — "안전성 확보에 필요한 기술적 조치를 하여야 한다"
> - **OWASP A05:2021** (보안 구성 오류) — HTTP 보안 헤더 미설정은 보안 구성 오류에 해당
> - **국가정보보안기본지침 제14조** — 정보시스템 보안 설정 관리

- `X-Content-Type-Options: nosniff` — MIME 스니핑 방지
- `X-Frame-Options: DENY` — 클릭재킹 방지
- `referrer: strict-origin-when-cross-origin` — 리퍼러 누출 방지
- **대상**: 6개 파일 전체

> 💡 **쉽게 말하면**: 해커가 우리 페이지를 악용하기 어렵게 만드는 **보안 잠금장치 3개**를 추가한 것입니다.
>
> | 태그 | 비유 | 효과 |
> |:---|:---|:---|
> | X-Frame-Options | "우리 화면을 다른 사이트에 몰래 넣지 마" | 피싱 사이트가 우리 페이지를 액자처럼 끼워 넣어 클릭을 유도하는 것(클릭재킹) 방지 |
> | X-Content-Type-Options | "파일 종류를 속이지 마" | 이미지인 척하는 악성 파일 실행 방지 |
> | Referrer Policy | "우리 주소를 외부에 다 알려주지 마" | 다른 사이트로 이동할 때 시스템 URL이 불필요하게 노출되는 것 방지 |

### 2-3. React 프로덕션 빌드 전환 ⚡

> 📜 **법적 근거**
> - **OWASP A05:2021** (보안 구성 오류) — "프로덕션 환경에서 디버그 모드를 비활성화하여야 한다. 디버그 모드가 활성화되면 스택 트레이스, 내부 경로 등 민감 정보가 노출될 수 있다"
> - **소프트웨어 개발보안 가이드** — 배포 시 디버그 코드 제거 의무

- `react.development.js` → `react.production.min.js`
- `react-dom.development.js` → `react-dom.production.min.js`
- **효과**: 디버그 정보 비노출 + 번들 크기 감소 + 성능 향상
- **대상**: 3개 파일 (React 사용 파일)

> 💡 **쉽게 말하면**: 개발용 도구를 빼고 **실전 배포용으로 교체**한 것입니다.
> 건물을 다 지은 뒤 **공사용 비계·가림막을 치우고** 깔끔하게 오픈하는 것과 같습니다.
> 불필요한 디버그 정보가 제거되어 페이지가 더 빨리 뜨고, 내부 구조가 외부에 노출되지 않습니다.

### 2-4. 에러 메시지 정제 🔐

> 📜 **법적 근거**
> - **OWASP A05:2021** (보안 구성 오류) — "에러 메시지를 통해 스택 트레이스, DB 경로 등 불필요한 내부 정보가 사용자에게 노출되어서는 안 된다"
> - **소프트웨어 개발보안 가이드 — CWE-209** (에러 메시지를 통한 정보 노출) — 에러 응답에 민감한 시스템 정보 포함 금지

- 기존: `"등록 오류: " + err.message` → 내부 구조 노출
- 변경: `"등록 중 오류가 발생했습니다."` + `console.error("[시스템]", err)`
- **대상**: `lost_and_found.html` (8건), `lost_and_found_admin.html` (6건)

> 💡 **쉽게 말하면**: 오류 발생 시 **내부 시스템 정보가 사용자 화면에 보이지 않도록** 한 것입니다.
>
> - 변경 전: `"등록 오류: Firestore quota exceeded at /data/facilities/..."` ← 해커가 DB 구조 파악 가능
> - 변경 후: `"등록 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요."` ← 친절한 안내만 표시
>
> 상세 오류 내용은 개발자 콘솔(F12)에서만 확인할 수 있습니다.

### 2-5. 입력 데이터 Sanitize 함수 추가 🛡️

> 📜 **법적 근거**
> - **OWASP A03:2021** (인젝션) — "사용자 입력은 항상 검증·필터링·새니타이징하여야 한다. 크로스 사이트 스크립팅(XSS) 공격은 입력값에 악의적인 스크립트를 삽입하여 발생한다"
> - **소프트웨어 개발보안 가이드 — CWE-79** (XSS) — 입력값에 대한 HTML 태그 필터링 의무
> - **개인정보보호법 제29조** (안전조치의무) — 기술적 보호조치

- `sanitizeInput(str, maxLen)` — HTML 태그·위험 문자 제거 + 길이 제한
- `sanitizePhone(str)` — 전화번호 형식만 허용 (숫자, 하이픈)
- **대상**: `lost_and_found.html`, `lost_and_found_admin.html`

> 💡 **쉽게 말하면**: 입력란에 **악의적인 코드를 넣어도 자동으로 걸러내는 방어 장치**입니다.
>
> - 변경 전: 분실물 이름에 `<script>해킹코드</script>` 같은 코드를 넣을 수 있음
> - 변경 후: `<script>`, `<img>` 같은 HTML 태그가 자동 제거됨
>
> 편지봉투에 **위험물질 검사기**를 설치한 것과 같습니다.

## 참고

- `X-Frame-Options`은 HTTP 헤더로 설정해야 완전히 동작. `<meta>` 태그는 일부 브라우저에서 무시될 수 있음
- GitLab Pages에서 HTTP 헤더 설정이 제한적이므로 `<meta>` 태그로 대체 조치
- 서버 사이드 헤더 설정은 향후 과제로 남김
