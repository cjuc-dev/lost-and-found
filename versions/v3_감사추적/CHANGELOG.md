# v3 — 감사 추적·세션 관리 (Phase 3)

> **작업일**: 2026-05-10  
> **작업 근거**: 개인정보보호법·안전성 확보조치 기준·OWASP 세션 관리 지침  
> **이전 버전**: v2_접근성개선

---

## 🎯 수정 목적

개인정보를 처리하는 시스템에서 **"누가, 언제, 무엇을 했는지"** 추적할 수 있어야 하고,  
사용하지 않는 접속은 **자동으로 차단**되어야 합니다.  
이 두 가지가 Phase 3의 핵심입니다.

---

## 📝 변경 내역

### 3-1. 감사 로그(Audit Log) 강화 📝

> 📜 **법적 근거**
> - **개인정보보호법 제29조** (안전조치의무) — "개인정보처리자는 개인정보가 분실·도난·유출·위조·변조 또는 훼손되지 아니하도록 안전성 확보에 필요한 조치를 하여야 한다"
> - **개인정보의 안전성 확보조치 기준 제8조** (접속기록의 보관 및 점검) — "개인정보처리시스템에 접속한 기록을 **6개월 이상** 보관·관리하여야 한다"
> - **개인정보의 안전성 확보조치 기준 제8조 제2항** — "접속기록에는 **식별자, 접속일시, 접속지 정보, 처리한 정보주체 정보, 수행업무**를 기록하여야 한다"

| 구분 | v2 (이전) | v3 (변경) |
|:---|:---|:---|
| 데이터 수정 로그 | ❌ 수정 전 값 미보존 | ✅ 변경 전·후 값을 함께 기록 |
| 상태 변경 로그 | ⚠️ 부분 기록 | ✅ 모든 상태 변경 기록 (보관중→수령 등) |
| 관리자 접속 로그 | ✅ 성공만 기록 (v1에서 적용) | ✅ **성공+실패** 모두 기록 |

> 💡 **쉽게 말하면**: 기존에는 "누가 분실물을 등록했다" 정도만 기록했는데, 이제는 "누가, 언제, 무엇을 어떻게 바꿨는지" (예: 상태를 '보관중'에서 '수령완료'로 변경) 상세하게 기록합니다.
>
> 만약 나중에 "왜 이 분실물이 삭제되었나?"라는 질문을 받으면, 로그를 보고 "5월 10일 오전 10시에 A시설에서 삭제했습니다"라고 답변할 수 있습니다.

**적용 파일**: `lost_and_found.html`, `lost_and_found_admin.html`

### 3-2. 세션 타임아웃 (자동 로그아웃) ⏰

> 📜 **법적 근거**
> - **개인정보보호법 제29조** (안전조치의무) — 안전성 확보에 필요한 기술적 조치
> - **개인정보의 안전성 확보조치 기준 제5조 제5항** — "개인정보처리자는 개인정보처리시스템에 대한 불법적인 접근을 차단하기 위하여 **일정시간 이상 업무처리를 하지 아니하는 경우에는 자동으로 시스템 접속이 차단**되도록 하여야 한다"
> - **OWASP 세션 관리 지침** — "비활성 세션은 가능한 짧은 시간(15~30분) 후에 타임아웃되어야 한다"
> - **국가정보보안기본지침 제15조** — 자동 잠금 기능 활성화

| 구분 | v2 (이전) | v3 (변경) |
|:---|:---|:---|
| 시설 담당자 세션 | ❌ 한번 로그인하면 영구 유지 | ✅ **30분 미조작 시 자동 로그아웃** |
| 관리자 세션 | ❌ 한번 로그인하면 영구 유지 | ✅ **20분 미조작 시 자동 로그아웃** |
| 만료 전 경고 | ❌ 없음 | ✅ **만료 5분 전 경고 알림** |
| 만료 시 처리 | ❌ 없음 | ✅ 화면을 로그인 페이지로 이동 + 세션 데이터 파기 |

> 💡 **쉽게 말하면**: 체육관 안내데스크에서 분실물 시스템에 로그인한 후 **자리를 비우면**, 30분 뒤 자동으로 로그아웃됩니다.
>
> **왜 필요한가?**
>
> | 상황 | 세션 만료 없으면 😰 | 세션 만료 있으면 ✅ |
> |:---|:---|:---|
> | 담당자가 점심 먹으러 감 | 아무나 와서 분실물 삭제·수정 가능 | 30분 후 자동 로그아웃 → 접근 차단 |
> | 관리자가 회의 중 | 다른 직원이 관리자 기능 무단 사용 가능 | 20분 후 자동 잠금 |
> | 공용 PC에서 로그인 후 방치 | 다음 사용자가 개인정보 열람 가능 | 자동 차단으로 개인정보 보호 |
>
> 법적으로 **"일정시간 미사용 시 자동 차단"**은 선택이 아니라 **의무**입니다.

**적용 파일**: `lost_and_found.html`, `lost_and_found_admin.html`

## ✅ 검증 항목

- [ ] 분실물 상태 변경 시 변경 전·후 값이 로그에 기록되는지 확인
- [ ] 관리자 로그인 실패 시 실패 로그가 기록되는지 확인
- [ ] 30분 미조작 시 시설 담당자 페이지에서 자동 로그아웃되는지 확인
- [ ] 20분 미조작 시 관리자 대시보드에서 자동 로그아웃되는지 확인
- [ ] 만료 5분 전 경고 알림이 표시되는지 확인
- [ ] 기존 기능(등록/조회/수정/삭제/폐기) 정상 동작 확인

## 📌 이 버전의 핵심 요약 (비개발자용)

> Phase 3는 **"누가 뭘 했는지 추적"**하고 **"자리 비우면 자동 잠금"**하는 기능입니다.

| 감사관 질문 | 우리 답변 |
|:---|:---|
| "개인정보 접속기록을 보관하고 있습니까?" | ✅ "모든 접속·데이터 변경 기록을 Firestore에 6개월 이상 보관합니다." |
| "접속기록에 어떤 정보가 포함됩니까?" | ✅ "세션 ID, 시설코드, 접속일시, 수행업무(등록/수정/삭제/상태변경)가 기록됩니다." |
| "미사용 시 자동 접속 차단 기능이 있습니까?" | ✅ "시설 담당자 30분, 관리자 20분 미조작 시 자동 로그아웃됩니다." |
| "접속 차단 전 경고를 합니까?" | ✅ "만료 5분 전 화면에 경고 알림이 표시됩니다." |
